# Academic-origin supplement study protocol

This is a development study for the frozen rewrite-origin classifier. The parent model is v2, SHA256 `8c8a23e4ecb5bdaaccee57516fb1d8f1b0703106748668b8af09e936846c915b`. On the independent 66-source academic development cohort v2 and both previous rewrite-origin challengers detected 66 of 66 machine paraphrases. The two cases in the ordinary development report give the older candidates an ECE of .50. Neither set measures human specificity on academic papers. [Academic development audit](paraphrase-development.md)

## Source projection and admission

1. The publisher-backed RAID projection targets 48 distinct machine-origin source groups in the stack role and 48 in isotonic calibration. Select one existing accepted academic paraphrase per source with a fixed seed and generator allocation. The child, exact clean machine parent and same-source human original each carry a normalized document ID, exact publisher ID, parent ID, model, word count, original text checksum and research text. Each projected record carries the source group, role, domain and target origin. Verify the child-to-parent link, label, group, revision and production gate. Only the eligible transformed child contributes a new fitting row. Preserve the one existing long human-origin academic paraphrase in each legacy fitting role.
2. The human projection uses published original scientific passages with documented provenance and a publication date before 2020. Require one designated passage per independent article family, a stable publisher identifier, original date with its source, publisher/repository revision, licensing terms, subject, document origin and transformation, plus normalized source/document hashes. Link versions, preprints and DOI aliases before assignment. Retain the native-human and rewritten-human categories in both the source manifest and the aggregate report.
3. Assign human papers to stack, calibration and independent human development using a fixed seeded group hash before scoring. Target 48 comparable native-human papers per fitting role and a separate development pool, ideally at least 66. For each role publish availability and accepted counts by origin, transformation, archive, discipline, word band, year and production refusal reason. Match on common scientific field and length where metadata supports it. Record overlap coverage and the unmatched source inventory before fitting. Report the achieved independent-control size and binomial uncertainty. The 48- and 66-source sample sizes are planning targets. Smaller cohorts with documented field and length overlap remain informative, with their observed denominators and uncertainty.
4. Verify document and source-family independence against the signed legacy fitting cohorts, original primary validation envelope, books/news matched stress, all 131 auxiliary academic document identities, independent cutoff controls and protected evaluation membership commitments. Compare both transformed and clean-parent document identities. Use the established normalized-text convention, known publisher aliases, exact source links and a documented cross-archive duplicate check. Print only aggregate support, exclusion counts and commitments. Every new row needs a fixed stack, calibration or independent development role.
5. Before collecting candidate features, freeze the corpus revisions, file hashes, eligibility and matching rules, retained order and document/group commitments for every role. Proceed to an origin comparison when there is credible common field/length support for both labels in each fitting role and independent human development. Publish deficiencies as source-coverage findings. Different disciplines supplied exclusively by different origin labels would make discipline a competing explanation for a score difference.

## Model and reproduction

Keep all 680 original stack rows, 1,346 calibration rows and 192 matched books/news documents per fitting role. The additive model uses the same 13 numeric Deep features, 769-value frozen encoder evidence, source weights and original v1 head SHA. Append the verified academic rows by stable order and store their numeric features in a separate resumable sidecar with source, role, exact extraction/runtime and weight bindings. For 48 machine and 48 human additions per fitting role, the resulting counts would be 968 stack and 1,634 calibration documents. Record the actual counts from the signed projection.

Use the fixed text-only rewrite-origin probe, SHA256 `f091eed2f254fdd5285ec8cf6ee595b93539d7207eac8b34da2972be173099b9`. Fit exactly two seven-leaf monotone histogram gradient-boosting stackers with L2 of 1, seed 42 and fixed probe anchors .50 and .75. Preserve the original 50% reference prior for isotonic calibration, length-specific support rule and 200 bootstrap curves. Bind the high cutoff to the original disjoint ASAP/ELLIPSE cohort under the original two-percent target and retained-sensitivity rule. The production feature vector contains text-derived measurements only. Genre, archive, publisher, dates, generator and origin tags are evaluation metadata.

## Frozen comparisons

Replay the unsupplemented v3 candidates at the corresponding anchors as the paired algorithm controls, and include the published v2 research incumbent as the fallback. Compare the exact 268 primary rows and 64 balanced books/news stress pairs using the same published gates, fixed source identities, smallest strata, raw probabilities, serving-rounded indices, thresholds and group-level paired diagnostics as v3. Report raw and calibrated academic results by source, origin, transformation and domain, including high-band human false positives with denominators and uncertainty. Report results on the 66 independent machine-origin rewritten groups and their clean machine controls separately from the disjoint human academic development pool. Track per-source error alongside pooled loss so a strong result from one archive cannot conceal failure on another.

The release owner freezes both candidate configurations, source projections, admission evidence and comparison rules before new development predictions. Selection and any final evaluation remain separate decisions. [Unchanged release comparison](rewrite-calibration-protocol.md)
